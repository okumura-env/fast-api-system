# ganesha-lecture スキル

ユーザーが入力したテーマに基づき、ガネーシャ×ナツキの対話コンテンツを生成する。
**まずMDファイルを出力**し、ユーザーの確認・修正指示を待つ。指示があればHTML化＋surgeデプロイを行う。

品質基準は「入社したての新卒社会人が読んでも腹落ちする明快さ」。

## 依存

- [references/character-usage.md](references/character-usage.md) — キャラクター設定・表情使い分け・対話パターン・MD記法ルール
- [references/term-dictionary.md](references/term-dictionary.md) — 専門用語→やさしい言葉の変換辞書
- `.claude/assets/avatars/` — ガネーシャ・ナツキのアバター画像
- HTML化時の依存（フェーズ2でのみ使用）:
  - `.claude/skills/ganesha-visual-explainers/references/base.html` — HTMLテンプレート本体（Tailwind CSS + Lucide Icons）
  - `.claude/skills/ganesha-visual-explainers/references/html-structure.md` — gvカラーシステム・Lucideアイコン・コンポーネントパターン
  - `.claude/skills/ganesha-visual-explainers/references/exemplar.md` — 模範解答の構造・再利用可能なHTMLスニペット

## フェーズ1: 精巧なMDファイルの生成

### Phase 0: リサーチ（サブエージェント）

トピックが **このプロジェクト（tokuyama-project）に関連するか** を判定し、調査方法を分岐する。

#### A. プロジェクト関連トピックの場合

「このプロジェクトの認証」「うちのDB設計」「このアプリのルーティング」など、tokuyama-projectのコード・設計・使用技術に関わるトピックの場合。

**2つのサブエージェントを並列起動する：**

```
// サブエージェント1: コードベース調査
Agent({
  subagent_type: "Explore",
  description: "プロジェクトのコード調査",
  prompt: `
    tokuyama-projectのコードベースを調査してください。

    【調査対象】{トピック名}（例: 認証の仕組み、ルーティング設計、データモデル等）

    調査手順：
    1. まず CLAUDE.md を読んでプロジェクト全体像を把握
    2. docs/ 内の関連仕様書を読む（architecture/, features/, db/, business/）
    3. トピックに関連するソースコード（app/配下）を読む
    4. マイグレーション（database/migrations/）があれば確認

    出力形式：
    - このプロジェクトでの実装方法（具体的なファイルパス・関数名・コード抜粋を含む）
    - 使用している技術・ライブラリ
    - 設計上の判断とその理由（わかる範囲で）
    - 関連ファイル一覧
  `
})

// サブエージェント2: 技術の一般知識を調査
Agent({
  subagent_type: "Explore",
  description: "技術の一般知識を調査",
  prompt: `
    以下の技術トピックについて一般的な知識を調査してください：
    【対象】{トピックの技術名}（例: Laravel Sanctum, Vue Router, Eloquent ORM等）

    調査項目：
    1. この技術の正確な定義（公式情報・信頼できる情報源優先）
    2. 仕組み・動作原理
    3. 典型的なユースケースや具体例
    4. 初心者がつまずきやすいポイント
    5. 関連する信頼できる情報源のURL

    結果は箇条書きで整理して返してください。
  `
})
```

**Phase 1以降では両方の結果を組み合わせて**、「このプロジェクトではこう実装されていて、その裏にはこういう仕組みがある」という解説を作る。テーブルやASCIIアートにはプロジェクトの実際のコード・ファイル構成・データフローを題材として使う。

#### B. 一般トピックの場合

プロジェクトに直接関係しないトピック。

```
Agent({
  subagent_type: "Explore",
  description: "トピックの調査",
  prompt: `
    以下のトピックについて徹底的に調査してください：
    【対象】{トピック名}

    調査項目：
    1. このトピックの正確な定義（公式情報・信頼できる情報源優先）
    2. 主要な概念・用語の一覧
    3. 典型的なユースケースや具体例3つ以上
    4. 初心者がつまずきやすいポイント
    5. 最新の動向・変更点
    6. 関連する信頼できる情報源のURL

    結果は箇条書きで整理して返してください。
  `
})
```

### Phase 1: ソース読み込み

1. リサーチ結果を整理し、情報の全体像を把握する
2. **Phase 0のリサーチ結果と照合**して抜け漏れを確認
3. 以下のreferencesを読み込む:
   - [references/character-usage.md](references/character-usage.md)
   - [references/term-dictionary.md](references/term-dictionary.md)
4. アバターバリアントを確認:

```bash
ls .claude/assets/avatars/ganesha/
ls .claude/assets/avatars/natsuki/
```

各バリアントの画像を Read で確認し、どんな感情・場面に合うか判断してから使う。

### Phase 2: 用語翻訳表を作成

専門用語を洗い出し、やさしい言葉に変換する。[references/term-dictionary.md](references/term-dictionary.md) を参照し、既存の変換を活用しつつ、トピック固有の用語も追加する。

| 技術用語 | やさしい言葉 | たとえ |
|---------|------------|--------|
| 例: コールバック関数 | チェック係 | 「何かあったら呼んでね」と登録しておく処理 |

### Phase 3: たとえ話を3つ以上考える

| 種類 | 例 |
|-----|-----|
| 身近な例 | 日常で触れるもの |
| 体験の例 | 誰もが経験したことがあるもの |
| 視覚的な例 | ASCIIアートやテーブルで表現できるもの |

### Phase 4: 情報を絞り込む

- 「まず覚える3つ」を決定
- 全体の中の位置づけを示す
- 優先度の低い情報は後半に配置

### Phase 5: キャラクター対話 + 図表を設計

[references/character-usage.md](references/character-usage.md) に準拠し、対話の流れと図表の配置を設計する。

**対話と図表の交互配置が最重要ルール。** 対話が3往復以上続いたら、必ず図表（テーブル・ASCIIアート・コードブロック）を挟む。

#### 解説の手法（必ず守ること）

- **結論から**答える。**タイトル**をつける
- **例え話**で導入し、実際の内容に**会話と図表で**マッピングする
- 偉人を「ワシの教え子」と称しエピソードを交える（テーマに合った偉人を選ぶ）
- **ASCIIアート図**・**テーブル**・**コードブロック**を活用
- **初心者が間違えやすいポイント**を丁寧に説明
- **なぜそうなるのか？ないと何が不便か？何が便利か？** などメリットの観点に必ず言及
- ナツキ👩‍💻がガネーシャ🐘の矛盾や曖昧さに鋭くツッコミを入れる
- 絵文字を多用して親しみやすくユーモラスに

#### その他の指針

- **概論 → 各論** — いきなり詳細に入らない
- **専門用語は初出で必ず解説**
- **たとえ話で身近な体験に結びつける** — たとえ話はテキストだけで済まさず図表化する
- **簡潔にまとめすぎない** — 理解に必要な情報量は削らない
- **図を早く見せる** — テキストが2段落以上続いたら図表を入れる
- **読者のレベルに言及しない** — 「初心者向け」「入門」等は使わない
- **日本語で** — 英語メインのトピックでも、図表は日本語で書く

#### 対話記法チェックリスト

- [ ] 対話記法: `🐘「セリフ」` `👩‍💻「セリフ」`
- [ ] バリアント記法: `🐘得意げ「セリフ」` `👩‍💻呆れ「セリフ」`
- [ ] 1吹き出し最大150文字
- [ ] 同じキャラの連続発言は3回以内
- [ ] 重要キーワードは `**太字**`
- [ ] 概念の対比にはテーブルを使用
- [ ] セクション間に `---` と見出しで区切り（見出しにアイコン絵文字）
- [ ] 構成: 結論ブロック（> 引用）→ 導入 → 概念解説（たとえ話→図表→本質）→ まとめ
- [ ] 「さすガネーシャや！✨」→ ナツキのツッコミで締め
- [ ] 最後は「はい、Oh, My God!! 🙏✨」
- [ ] HTMLタグは使わない（純粋なMarkdown）

### Phase 6: 対話コンテンツの生成

Phase 5の設計に基づき、MDコンテンツを生成する。

### Phase 7: 批判的レビュー（サブエージェント）

HTML化の前に、**MD内容を忖度なくレビュー**する。

```
Agent({
  subagent_type: "general-purpose",
  description: "対話コンテンツの批判的レビュー",
  prompt: `
    あなたは「ITに詳しくない新卒社会人」です。
    プログラミング経験はゼロ、スマホは使えるがアプリの仕組みは知りません。

    以下のMD対話コンテンツを読んで、**忖度なく**批判してください：

    【MDファイルパス】{path}

    ## レビュー観点

    1. **わからない言葉**: 説明されていても難しい言葉はどれか
    2. **たとえ話の違和感**: ピンとこない、逆に混乱するたとえはないか
    3. **情報過多**: 読むのが辛くなる部分、スキップしたくなる部分
    4. **キャラクターの不自然さ**: セリフが専門家っぽすぎないか
    5. **結局何がわかったか**: 読み終わって説明できる自信があるか

    ## 出力形式

    ### 致命的な問題（これがあると読めない）
    - ...

    ### 改善すべき点（直せばもっと良くなる）
    - ...

    ### 良かった点（このまま残すべき）
    - ...

    ### 総評
    5段階評価: ⭐⭐⭐☆☆（3/5）のように
    一言: 「○○だから△△な人には難しい」のように
  `
})
```

### Phase 8: ブラッシュアップ

Phase 7のレビュー結果を踏まえてMDを修正する。

**優先度**:
1. 致命的な問題 → 必ず修正
2. 改善すべき点 → 可能な限り対応
3. 良かった点 → 維持

**よくある修正パターン**:
- 用語の言い換え・補足追加
- たとえ話の差し替え・追加
- 長いセクションの分割
- キャラクターのセリフをより素朴に

### Phase 9: MDファイルの保存

```bash
mkdir -p .claude/skills/ganesha-lecture/output/{YYYY-MM-DD}
```

ファイル名: `.claude/skills/ganesha-lecture/output/{YYYY-MM-DD}/{テーマのkebab-case}.md`

### Phase 10: 品質チェックリスト

保存前に以下を確認：

#### 必須

- [ ] 全ての技術用語にやさしい言葉での説明がある
- [ ] たとえ話が3つ以上ある
- [ ] 導入・中間・まとめにキャラクター対話がある
- [ ] 「まず覚える3つ」のような絞り込みがある
- [ ] コード例の前に「このコードがやること」の説明がある
- [ ] 結論ブロック（> 引用）が冒頭にある
- [ ] 最後は「はい、Oh, My God!! 🙏✨」（決めポーズ）

#### 対話

- [ ] 1吹き出し最大150文字
- [ ] 同じキャラの連続発言は3回以内
- [ ] ガネーシャの関西弁が一貫している
- [ ] 偉人エピソードが1つ以上ある
- [ ] ナツキのツッコミが少なくとも1つある
- [ ] 「さすガネーシャや！✨」→ ナツキのツッコミで締め

#### 図表

- [ ] 対話と図表が交互に配置されている（対話だけで3往復以上続いていない）
- [ ] 図表だけで3つ以上続いていない（必ず対話を挟む）
- [ ] ASCIIアート・テーブル・コードブロックが適切に使い分けられている

### Phase 11: 結果の報告と確認

```

.claude/skills/ganesha-lecture/output/{YYYY-MM-DD}/{ファイル名}.md

内容を確認して、修正があればお知らせください。

```

**ここでフェーズ1は完了。ユーザーの指示を待つ。**

## フェーズ2: HTML化＋surgeデプロイ（ユーザーの指示があった場合のみ）

ユーザーが「HTMLにして」「デプロイして」「surgeで公開して」等と指示した場合に実行する。

MDの中の **ASCIIアート図・テーブル・コードブロック部分** をリッチなHTMLビジュアルに変換し、対話テキスト部分はHTML対話UIに変換する。

### Phase 12: HTML化リソースの読み込み

以下の3つを読み込む（ganesha-visual-explainers と共有）:

1. `.claude/skills/ganesha-visual-explainers/references/base.html` — テンプレート本体
2. `.claude/skills/ganesha-visual-explainers/references/html-structure.md` — コンポーネントパターン・カラーシステム
3. `.claude/skills/ganesha-visual-explainers/references/exemplar.md` — 模範構造・HTMLスニペット

### Phase 13: スタンドアロンHTMLの生成

`base.html` をテンプレートとしてコピーし、`html-structure.md` のコンポーネントパターンと `exemplar.md` の模範構造に準拠してHTMLを生成する。

#### MDからHTMLへの変換ルール

MD内の各要素を、`html-structure.md` のコンポーネントパターンに変換する:

| MD要素 | HTML変換先 |
|--------|-----------|
| `🐘「セリフ」` / `👩‍💻「セリフ」` | アバター付き吹き出しUI |
| `🐘得意げ「セリフ」` 等バリアント | 対応するバリアント画像の吹き出し |
| テーブル（`\| ... \|`） | gvカラーシステムのスタイル付きテーブル |
| ASCIIアート図・図解 | **`html-structure.md` 末尾「図解パターンの使い分け」テーブルを参照し、説明内容に合うパターンを選択する**（ASCIIアートをそのまま貼り付けない） |
| コードブロック | `html-structure.md` のコード例パターン（日本語解説付き） |
| `> 引用` 結論ブロック | `exemplar.md` の結論ボックスパターン |
| `**太字**` | 吹き出し内は `text-gv-secondary font-bold` |
| `---` セクション区切り | セクションカード区切り |
| たとえ話 | `html-structure.md` のたとえ話ボックスパターン |

画像は外部ファイルとして `images/` ディレクトリ内を相対パスで参照する。外部リンクには `target="_blank" rel="noopener noreferrer"` を付与する。

### Phase 14: HTMLファイルの保存

MDファイルと同じ日付ディレクトリに保存:

ファイル名: `.claude/skills/ganesha-lecture/output/{YYYY-MM-DD}/{テーマのkebab-case}.html`

### Phase 15: surgeでデプロイ

```bash
bash .claude/skills/ganesha-lecture/scripts/deploy.sh .claude/skills/ganesha-lecture/output/{YYYY-MM-DD}/{ファイル名}.html {テーマのkebab-case}
```

### Phase 16: INDEX.md の更新

デプロイ成功後、`.claude/skills/ganesha-lecture/INDEX.md` のテーブル末尾に新しい行を追加する。

```
| {今日の日付} | {テーマ日本語名} | [MD](output/{YYYY-MM-DD}/{ファイル名}.md) | [HTML](output/{YYYY-MM-DD}/{ファイル名}.html) | https://{subdomain}.surge.sh |
```

**既存の行は変更しない。末尾に追記する。**

### Phase 17: 結果の報告

```
デプロイ完了。

- URL: https://{subdomain}.surge.sh
- HTML: .claude/skills/ganesha-lecture/output/{YYYY-MM-DD}/{ファイル名}.html
- MD（編集用）: .claude/skills/ganesha-lecture/output/{YYYY-MM-DD}/{ファイル名}.md
- INDEX.md を更新しました
```
